# 一套企业系统的拆解：统一认证 + 智能客服

这十篇不是教程，是从一份真实运行过的企业代码里读出来的十块结构：一个统一认证中心（Go + Gin），一个智能客服平台（Flask + Celery + Redis + ES），以及一条把它们串起来的授权链路。

读代码的价值不在「这段写法对不对」，而在「它当时为什么这么选」。所以每篇都按同一个骨架写：先讲这套系统要解决什么，再讲它实际怎么实现（带代码和表结构），最后给出「可以直接抄的部分」和「建议加固的地方」。文中标为「已知缺陷」的段落不是编出来的案例，是代码里真实存在的问题——保留它们，是因为评审时最有讨论价值的往往就是这些地方。

对应归档里的 4 个目录（去重后有效源码约 1500 个文件），是四套可复用的工程：认证中心、它的加固分支、智能客服平台、机器人平台。

| 目录 | 角色 | 技术栈 |
| --- | --- | --- |
| `sso/` | 统一认证中心（SSO），多租户、多应用的 OAuth 2 服务 | Go 1.12 + Gin + jinzhu/gorm + redigo + gin-swagger |
| `sso_pwd/` | 上一项的加固分支：密码传输加密 + 密码策略 | 同上，新增 AES-CBC 解密链路 |
| `webot3/` | 智能客服平台（在线客服 + 调度 + BI + 工单） | Python 3.6 + Flask 1.1 + flask_restplus + SQLAlchemy + Celery 4 + Redis + MySQL + ES |
| `webot3_robot/` | 机器人平台（FAQ 检索 + 多轮任务型对话） | 同上，独立一套 Flask 服务 |

它们之间是一条完整的链路：

```
浏览器 / APP
    │  ① 登录、拿 code、换 token
    ▼
统一认证中心 (sso)  ──② /api/oauth/user/me, /permission ──►  业务子系统
    │                                                        （客服平台 admin_api）
    │  ③ 会话中间件校验 user_token + 菜单权限
    ▼
智能客服平台 (webot3) ──④ Celery 分级队列 / 规则引擎调度 / Redis 队列 ──► 客服工作台
                      ──⑤ 机器人平台 (webot3_robot) 提供 FAQ 与多轮任务作答
```

## 五、怎么用这组文章

- **60 分钟**：01 + 04 + 10（认证链路、调度核心、安全治理），三个最有方法论价值的主题。
- **90 分钟**：加 05 + 08，把「工程骨架」和「领域建模」补齐。
- **深度工作坊**：02 + 06 适合现场写代码复现（跨语言哈希兼容、缓存防击穿），配一组测试向量很出效果。

每篇末尾都有「可复用的结论」清单，可直接摘成 slides；标为「已知缺陷」的段落适合作为评审环节的讨论题。
